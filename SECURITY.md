# Security policy

## Supported version

Security fixes are applied to the latest public release. Version 1.0.x is the
currently supported line.

## Reporting a vulnerability

Please use GitHub's private vulnerability-reporting feature for the repository.
If that feature is unavailable, contact the maintainer privately through the
contact method listed on the maintainer's GitHub profile.

Include:

- A concise description of the issue and its impact
- Affected version and environment
- Reproduction steps or a minimal proof of concept
- Suggested mitigation, if known

Do not include credentials, nonpublic personal information, live investigation
records, or other sensitive case data. Allow reasonable time for validation and
remediation before public disclosure.

## Security and compliance boundary

This is a local portfolio MVP, not production-ready compliance software. It
does not include authentication, authorization, secrets management, encrypted
case storage, multi-user isolation, supervisory approval, high-availability
controls, or a production security review.

A suspected sanctions match, ownership connection, or data-quality issue is an
analytical matter rather than a software vulnerability. Use a standard issue
for reproducible defects involving public or fictional data, without naming
nonpublic subjects.
